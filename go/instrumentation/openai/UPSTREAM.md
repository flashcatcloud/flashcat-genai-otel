# Differences from upstream

The baseline is `open-telemetry/opentelemetry-go-compile-instrumentation@1daafa0b` (2026-11-11), licensed under Apache-2.0.
Upstream uses `OtelMiddleware()` with `otelc` compile-time injection. This module provides middleware users register explicitly with `option.WithMiddleware(flashcatopenai.Middleware())`.

| File in this module | Baseline | Changes |
|---|---|---|
| `middleware.go` | `instrumentation/github.com/openai/openai-go/v3/middleware.go`, `pkg/netutil/http.go` | Removed dependencies on `otelc/pkg/*` (`hook.go`, `runtime.SuppressHTTPClientInstrumentation`, and the logger) and inlined `HTTPServerEndpoint`. Removed global tracer and meter lookups at package initialization. The tracer is resolved per request, with an optional `WithTracerProvider` override, so the middleware can be constructed before `flashcatgenai.Init`. Intercepts only POST requests (upstream matches path suffixes and also intercepts GET `/chat/completions/{id}`). Added coverage for the Responses API (`/responses`), which upstream does not cover. Replaced the one-time `sync.OnceValue` check of `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT == "true"` with a per-request call to `flashcatgenai.ContentCaptureEnabled()` (or `WithCaptureContent`). Moved content from span events (`gen_ai.content.prompt` / `gen_ai.content.completion`) to the current GenAI semantic conventions' JSON attributes `gen_ai.input.messages` / `gen_ai.output.messages` / `gen_ai.system_instructions`, including tool calls. Removed the deprecated `gen_ai.system`. Records usage only when the response includes it (upstream records 0 when usage is missing). Added `openai.api.type`. Uses known semantic convention values for `gen_ai.provider.name` (`azure.ai.openai`, `moonshot_ai`, `gcp.gen_ai`) and `dashscope` for DashScope, matching the Python DashScope instrumentation (upstream uses `qwen`). Uses `ErrorType` from `semconv/v1.40.0` for `error.type` |
| `streaming.go` | `instrumentation/github.com/openai/openai-go/internal/streaming/streaming.go` | Records time to first chunk using `gen_ai.response.time_to_first_chunk` from the semantic conventions (double, in seconds). Records this timing only for the first chunk with non-empty output (text, a refusal, or a tool call). Upstream records `gen_ai.response.time_to_first_token` (int, in microseconds) on the first line. Renamed `gen_ai.request.is_stream` to `gen_ai.request.stream`. Accumulates streamed tool call arguments by index. Handles Responses streams separately (they end with `response.completed / incomplete / failed` and omit `[DONE]`). Uses the complete response in the terminal event for usage and output. Locks Read / Close (upstream uses only an atomic flag, so lineBuffer can race when a different goroutine closes the stream). Increased the content limit from 16 KiB to 32 KiB and changed the truncation suffix to `…[truncated]`, matching the core module |
| `messages.go` | `contentFromJSON` comes from `v3/middleware.go` | The remaining code assembles message JSON and was written for this module |
| `responses.go`, `option.go` | — | Written for this module |

The upstream v1 / v2 directories were omitted (only openai-go v3 is supported), along with `hook.go` (the otelc injection hook).

Metrics still use upstream's `gen_ai.client.operation.duration`. The GenAI semantic conventions (now in `open-telemetry/semantic-conventions-genai`) switched to `gen_ai.client.inference.duration` for inference. Upstream has yet to adopt it, and this module continues to use the upstream metric for now.
